How to connect Microsoft Entra ID, Google or Okta

Microsoft Entra ID: App registrations › New registration, a Web redirect URI (above). Issuer https://login.microsoftonline.com/<directory id>/v2.0; the Application (client) id; Certificates & secrets › New client secret. Add the optional claim email.

Google Workspace: Google Cloud console › APIs & Services › Credentials › OAuth client id (Web application), the redirect URI above. Issuer https://accounts.google.com.

Okta: Applications › Create App Integration › OIDC, Web Application, the redirect URI above as the sign-in redirect. Issuer https://<your-org>.okta.com/oauth2/default; assign the app to people.

How to connect ADFS, Okta or Microsoft Entra ID

ADFS: AD FS Management › Relying Party Trusts › Add (claims aware), import our metadata file (or enter the entity ID as identifier and the reply URL as a SAML 2.0 WebSSO endpoint). Claim rule: send LDAP attribute E-Mail-Addresses as E-Mail Address, and transform it to Name ID (Email). Then upload https://<adfs host>/FederationMetadata/2007-06/FederationMetadata.xml here.

Okta: Applications › Create App Integration › SAML 2.0. Single sign-on URL: the reply URL; Audience URI: the entity ID; Name ID format EmailAddress, Application username Email. Assign people, then upload the app's metadata (Sign On › SAML Signing Certificates › Actions › View IdP metadata).

Microsoft Entra ID: Enterprise applications › New application › Create your own (non-gallery) › Single sign-on › SAML. Basic SAML Configuration: Identifier = entity ID, Reply URL = reply URL (or upload our metadata file). Leave token encryption off. Download Federation Metadata XML and upload it here; assign users and groups.
