These checks cover every place the console asks a model: prompts, AI steps in pipelines, the AI Assistant, Ask your data,
the file chat and transcription. Four rules hold everywhere and are tested on purpose:

- **A model's answer is a DRAFT** for a person to check, never a decision.
- **The AI Assistant refuses to write to a database.** Write Database is switched off: the assistant says so and offers
  a file, a bucket or a webhook instead; it never offers to go ahead.
- **It never invents a file, a collection or a column.** When you name one the workspace does not have, it says so and
  draws nothing that reads it.
- **It asks before it acts.** Anything that changes something comes back as a card to confirm.

**Before you start:** a working model connection (a local model is fine; answers may take a minute). A synthetic file in
storage, such as `qa/orders.csv` with columns `order_id`, `status`, `amount`. A short synthetic recording (`.mp3` or
`.m4a`) for transcription. AI calls are billed like any other work, tries included.

> **Warning:** Every answer in this area is a model's draft. A check passes on what the console does with the answer (it
> shows its sources, holds it, refuses, asks first), not on whether the model's words are clever.

## Example
At Summit Valley the tester asks the AI Assistant to write the day's orders into the store database. It answers that
writing rows into a database can't be done here, because the step for it is switched off, and offers to save the rows as
a file, upload them to a bucket or send them to a webhook. Asked to read a file the workspace does not have, it names
the file and draws nothing.
